# pi-history-tree

A read-only history browser for pi that lets you revisit your prompts and the assistant’s final replies without switching branches or changing your session.

![History Tree showing a searchable list of user messages](docs/images/history-tree-example.png)

English · [简体中文](README.zh-CN.md)

## How is it different from pi’s built-in Tree?

Pi’s built-in `/tree` is for navigating session history and switching branches. **`/history-tree` is for reading it.**

- **Less noise:** the tree lists only your messages; the reader shows your prompts and final replies by default, hiding thinking, tool calls, and intermediate steps.
- **Read, don’t navigate:** Enter opens a separate reader at the selected message. It does not move the active session position, create a branch, or send a model request.
- **Branch-aware:** consecutive messages stay at the same indentation level; only forks add a level. Reading follows one branch at a time, without mixing messages from other branches.
- **Keep your place:** Esc returns to the tree with your search and selection preserved. Press Esc again to return to your conversation.
- **Details when needed:** Ctrl+P switches to the full recorded process, including tools, thinking, and compaction summaries.

This is an independent extension. It does not modify pi’s core or replace `/tree`.

## Installation

Requires pi. Tested with `@earendil-works/pi-coding-agent` **1.4.0**.

### Install from npm (recommended)

Install the published package directly—no repository checkout required:

```bash
pi install npm:pi-history-tree
```

To pin a specific release:

```bash
pi install npm:pi-history-tree@0.1.0
```

In an existing pi session, run `/reload`. New pi sessions load the extension automatically.

### Install from a local checkout (for development)

If you want to modify the extension, clone or download this repository and run the following **from the repository directory**:

```bash
pi install .
```

This registers the local package in your user-level pi configuration. Keep the repository in place: pi loads it directly from that directory.

In an existing pi session, run `/reload`. New pi sessions load the extension automatically.

### Try it without installing

Try the npm package for a single pi invocation:

```bash
pi -e npm:pi-history-tree
```

Or try your local checkout:

```bash
pi -e /absolute/path/to/pi-history-tree/src/index.js
```

Both load the extension for that invocation only, without changing your configuration.

If switching from a local installation to npm, remove the local registration first to avoid loading both sources:

```bash
pi remove /absolute/path/to/pi-history-tree
pi install npm:pi-history-tree
```

This removes the pi registration, not your repository directory.

## Usage

Run this inside pi:

```text
/history-tree
```

1. Type to search your messages, then use **↑ / ↓** to select one.
2. Press **Enter** to open the reader at that message.
3. Scroll through the conversation with **↑ / ↓** or **PgUp / PgDn**.
4. Press **Esc** to return to the tree, then **Esc** again to close it.

If the selected message belongs to the active branch, that branch opens directly. Otherwise, if multiple continuations exist, you choose which one to read. `*` marks messages on the active branch.

### Controls

**History Tree**
- Type to search; Backspace edits the query. Search also matches message IDs.
- ↑ / ↓ selects a message; PgUp / PgDn moves by a page.
- Enter opens the reader; Esc exits even when a search query is present.

**Reader**
- ↑ / ↓ scrolls; PgUp / PgDn turns pages; Home / End jumps to the beginning or end.
- Ctrl+P toggles between **prompts + final replies** and the **full process**.
- Esc returns to the tree.

## Notes

- “Final reply” is inferred from recorded completion status, not generated by a model. Incomplete or unconfirmed replies show a short notice; use Ctrl+P to inspect the original process.
- Images appear as placeholders. Tool output is limited to what was saved; output truncated before saving cannot be recovered.
- The reader uses a snapshot. If the agent is still running, it continues normally; close and reopen the browser to see newer messages.
